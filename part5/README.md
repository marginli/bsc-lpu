# LPU 管線 — 三個檔案

PART 4 那十六支程式，整合成可以帶著走的三個檔案。

| 檔案 | 行數 | 做什麼 |
|---|---|---|
| `run_lpu.sh` | 55 | 在終端機一鍵跑完：檢查環境 → 跑 → 核對 → 列出產出 |
| `run_lpu.py` | 1,050 | 十四條指令，收成十二個函式（指令 10＋11、12＋13 各併成一個）。只管「先做什麼、再做什麼」 |
| `lpu_lib.py` | 561 | `Config`（所有參數）、`Brain`（資料與座標換算）、七個步驟的函式、畫圖 |
| `expected.json` | 47 項 | PART 3 的「怎麼確認它做對了」，寫成機器可以核對的形式 |

`expected.json` 不是程式，是驗收表。PART 4 最大的教訓是**驗收表比指令本身有用**
——指令 4 的表對不上，才追出密度場的定義寫錯了。所以把那些表留下來，
而且留成跑得動的形式。

---

## 一、新機器要裝什麼

**只有三個套件。**

```bash
python3 -m pip install 'numpy>=1.24' 'scipy>=1.10' 'matplotlib>=3.6'
```

| 套件 | 這裡測過的版本 | 用在哪 |
|---|---|---|
| `numpy` | 1.26.4 | 全部 |
| `scipy` | 1.15.3 | `ndimage`（平滑、膨脹、距離轉換、填洞）、`spatial.distance.pdist`、`cluster.hierarchy.linkage`／`fcluster` |
| `matplotlib` | 3.8.0 | 七張圖 |

Python **3.11.7** 是實際跑過的版本。程式碼在 3.12 的剖析器下也讀得過，
但這台機器的 3.12 沒裝套件，所以沒有真的在 3.12 上跑過一遍。
3.9／3.10 沒測過——程式用了 `from __future__ import annotations`，
`X | None` 那種寫法理論上在舊版不會出問題，但沒測過就是沒測過。

**沒有用到**：pandas、scikit-learn、scikit-image、trimesh、nrrd、PIL。
等值面是用 `ndimage` 的門檻加填洞做的，不需要 marching cubes。

## 二、資料要一起搬，而且資料才是重量

程式全部加起來 **84 KB**（四個檔案）。資料 **277 MB**。
把三個檔案複製到另一台機器沒有用，它們會找不到東西可以算。

用得到的檔案只有八個：

| 來自 | 檔案 | 大小 | 是什麼 |
|---|---|---|---|
| D03 | `work/labels_fc_1um.npy` | 173.2 MB | 75 個腦區的標籤體積 |
| D03 | `work/labels_fc_meta.json` | 1 KB | 格距與原點 |
| D03 | `D03_labels_meta.json` | 2 KB | 腦區名字 |
| D03 | `D03_fc_to_fcwb_affine.json` | 1 KB | 座標框轉換矩陣 |
| D06 | `work/vox.npy` | 45.4 MB | 骨架體素編號 |
| D06 | `work/nid.npy` | 45.4 MB | 每個體素屬於哪顆神經元 |
| D06 | `work/dep.npy` | 11.3 MB | 每個體素離細胞本體多遠 |
| D06 | `work/neurons.csv` | 1.6 MB | 28,573 顆神經元的名字 |

**打包成 39 MB：**

```bash
python3 run_lpu.py pack --pack-to ~/lpu_data
```

壓縮之後 277 MB → 38.6 MB（14%）。標籤體積壓到 **0.6%**，因為它幾乎全是零與大片同值。
程式讀得懂 `.npz`，所以另一台機器不必先解開；代價是載入多花 0.4 秒，
相對於整條管線的 166 秒可以忽略。

## 三、怎麼跑

```bash
./run_lpu.sh                              # 用內建的預設路徑
./run_lpu.sh ~/lpu_data/D03 ~/lpu_data/D06   # 換機器時把兩個資料目錄傳進來
```

或分開跑：

```bash
python3 run_lpu.py check     # 只檢查環境與資料，不算任何東西
python3 run_lpu.py all       # 從頭跑到尾
python3 run_lpu.py 4 5 6     # 只跑其中幾條指令
python3 run_lpu.py verify    # 核對 out/ 裡的結果與 expected.json
```

路徑有三種指定方式，優先序由高到低：命令列 `--d03 / --d06 / --out`、
環境變數 `LPU_D03 / LPU_D06 / LPU_OUT`、`Config` 裡的預設值。

## 四、安裝與執行時要注意的七件事

**1. `matplotlib` 一定要先設 Agg 後端。**
沒有螢幕的機器（伺服器、容器、`ssh` 進去的工作站）如果直接 `import pyplot`
會找不到顯示裝置而報錯。程式把這件事收在 `lpu_lib.setup_matplotlib()` 裡，
每張圖都經過它，所以只有一個地方需要對。

**2. 圖裡不要放中文。**
新機器不一定裝了中文字型。字型不在，matplotlib 不會停，它會印一堆
`Glyph missing from font` 然後把每個字畫成空白方塊——**圖照樣存檔，只是不能看**。
七張圖的文字全部是英文，就是為了避開這件事。

**3. 版本要鎖，理由跟一般專案不一樣。**
AL_R 的熱點有 3,130 個體素、4,896,885 對距離，但**相異的距離值只有 557 種**——
體素在整齊的格子上，距離會大量重複。UPGMA 遇到平手時選哪一對，取決於它們在
陣列裡的位置。所以體素順序一換，答案就會變（高度 6 打亂九次得到 13、13、13、14、14、14、15、15、15）。
換一個 scipy 版本，如果 `linkage` 的內部實作動過，同一份資料可能給出不同的群數。
**這條管線的可重現性比一般專案脆弱，鎖版本不是保守，是必要。**

**4. 記憶體要留 4 GB。**
實測峰值 **2.5 GB**，發生在指令 14 跑到 ME_L（15,203 個熱點體素，距離矩陣 0.86 GB，
加上 `linkage` 的內部複本）。其他每一步都在 1.1 GB 以下。
筆電跑得動，但別放進 2 GB 的容器。

**5. 不要用 `--user` 把套件裝進 conda 環境。**
`pip install --user` 裝到 `~/.local`，但 conda 的 python 會先看環境裡的 `site-packages`，
結果是「裝了卻沒生效」或「兩個版本打架」。在 conda 裡就用 `conda install`，
或至少確認 `python3 -m pip` 指的是同一個 python。`run_lpu.py check` 會把
實際載到的版本印出來，用它確認。

**6. 別為了「跑快一點」去調 BLAS 執行緒數。**
`OMP_NUM_THREADS` 之類的設定不會改變結果（`pdist`／`linkage` 是單執行緒的 C 迴圈），
但會讓你以為調過了。真正的瓶頸是 ME_L 那一區的 1.15 億對距離，那是演算法的複雜度，
不是設定問題。

**7. 這條管線的瓶頸不是算力，是資料。**
全腦 75 區跑完只要 94 秒。但 **54 個腦區的 LN 候選少於十顆**，根本沒有東西可以分群。
換一台更快的機器不會讓這 54 區變得可分析。

## 五、實測

在這台機器上（Python 3.11.7 / numpy 1.26.4 / scipy 1.15.3 / matplotlib 3.8.0）：

| | |
|---|---|
| 整條跑完 | 166 秒 |
| 其中指令 14（全腦 75 區） | 94 秒 |
| 峰值記憶體 | 2.5 GB |
| 產出 | 7 張圖、16 份 JSON、8 個 `.npy` 中間檔，共約 34 MB |
| 核對 | 47 項全部通過 |

**可攜性是驗過的，不是宣稱的**：把這四個檔案（84 KB）複製到一個空目錄，
只給它打包後的 39 MB 資料，重跑一遍，
**16 份 JSON 與 7 張 PNG 全部與原本逐位元組相同**。

## 六、有一步會停下來

指令 9（滾雪球招募）**在這份資料上沒有可用的操作區間**。
掃「撐大 2–5 格 × 重疊門檻 0.3–0.7」共 20 種組合，每一種的結果不是 1（只有種子）
就是 723（整池），沒有任何一種收到一部分。

主程式預設**會在這裡停下來**，不往下產出看起來完整、其實沒有意義的結果。
要繼續，得明確加上 `--force-recruit`——加了之後，後面每一個數字都建立在
「撐大 4 格」這一種讀法上，而那是唯一跑得動的讀法，不是驗證過的讀法。

`run_lpu.sh` 帶著這個旗標，並且在腳本裡把理由寫在旗標旁邊。
